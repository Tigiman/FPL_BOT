# FPL Deadline Reminder Bot

Гибрид: архитектура твоего старого бота (APScheduler — job ставится на точное время дедлайна минус 24ч/2ч, а не крутится в цикле) + фикс бага с "тихой пропажей" напоминания + текущий формат сообщения (4 часовых пояса).

## Что изменилось относительно старой версии

1. **Состояние теперь на диске (`STATE_FILE`), а не только в памяти.** В старой версии `scheduled_reminders` жил только в RAM: если контейнер перезапускался ровно в узкое окно между наступлением времени отправки и фактическим срабатыванием job'а — напоминание молча терялось навсегда (код видел `fire_at <= now` и просто помечал как "уже прошло", не проверяя, было ли оно реально отправлено).
2. **Досылка пропущенных окон.** Если бот не работал (простой, редеплой) и окно `-24ч`/`-2ч` уже наступило, а дедлайн ещё не прошёл — при следующей синхронизации бот досылает напоминание сразу, а не выбрасывает его.
3. **Перепроверка дедлайна перед фактической отправкой** — если FPL перенесли дедлайн после того, как job был запланирован, бот это увидит и либо переставит job на новое время, либо отправит с актуальным временем.
4. **Часовые пояса**: Минск, Варшава/Вильнюс, Ереван, Израиль (без Berlin).
5. Один `AsyncIOScheduler` вместо двух (в старой версии было избыточно два отдельных инстанса).

## Переменные окружения

Названия оставил как в твоём старом боте (`BOT_TOKEN`, `CHAT_ID`) — если он уже был задеплоен на Railway, можно просто переиспользовать те же значения.

- `BOT_TOKEN` — токен от @BotFather
- `CHAT_ID` — id группы (отрицательное число для групп)
- `STATE_FILE` — путь к файлу состояния, по умолчанию `/tmp/...` (см. пункт про volume ниже)
- `RECHECK_INTERVAL_HOURS` — как часто дополнительно перепроверять API помимо точных job'ов, по умолчанию 6

## Деплой на Railway

Тот же порядок, что и раньше:
1. Запушить папку в GitHub / `railway up` из CLI.
2. Start Command: `python bot.py` (или через `Procfile`).
3. Задать `BOT_TOKEN` и `CHAT_ID` в Variables.
4. (Рекомендуется) Volume на `/data` + `STATE_FILE=/data/fpl_reminder_state.json`, чтобы state переживал редеплои и полностью исключить даже теоретический дубль на границе отправки.

## Что можно поменять

- `TIMEZONES` — список поясов в `bot.py`.
- `REMIND_HOURS` — за сколько часов напоминать (сейчас 24 и 2).
- `RECHECK_INTERVAL_HOURS` — частота фоновой пересинхронизации.
- Текст сообщения — `format_message`.
